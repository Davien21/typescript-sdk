Keep previously granted OAuth scopes when a `401` leads to a new authorization. Automatic `401` handling in Streamable HTTP and legacy SSE adds the token's granted scope and every scope the transport has challenged or requested to the scope it selects. The refresh token is still tried first, values the authorization server does not advertise in `scopes_supported` are dropped, and non-interactive providers (no `redirectUrl`) retain nothing. If the authorization server then answers the callback with `invalid_scope`, `finishAuth()` drops the stored tokens and the accumulated scope, so the next `401` asks for the challenge alone. A step-up scope joins the transport's scope only once a token for it is saved (the token's reported scope when there is one), so a refused or declined scope is not requested again; parallel step-ups still widen one request. `auth()` accepts a new `priorScope` option for this, and `UnauthorizedContext` gains `accumulatedScope` and `resourceMetadataUrl`.
